# Which part of the code is Persona Core and which belongs to a feature module (#13843, part of #13430;
# docs/architecture/core-and-modules.md "Classification").
#
# Checked by scripts/test/test_module_classification.py, which fails when a unit below matches no line (a new package,
# directory or Gradle project nobody classified) and when a line matches nothing (stale: the unit moved or was removed).
#
# Units, one per kind:
#   go      every Go package directory (a directory with a tracked .go file, testdata left out) under server/ and sdk/go/
#   apple   every directory apple/<name>, apple/Persona/<name> and apple/Packages/<name>
#   gradle  every project android/settings.gradle.kts includes
#   web     every directory under web/src, one and two levels deep
#
# Lines:
#   module <id>                    declares a module id (#13430 section 2, plus the modules already built)
#   <kind> <unit> <core|id>        classifies one unit; the most specific line wins
#   <kind> <unit>/... <id>         the directory and everything below it (go, apple, web); never core, so a new
#                                  directory cannot become core without a line of its own
#   <kind> <prefix>/* *            each directory under a module root belongs to the module its name says
#   gradle :module:* *             the same for Gradle projects
# A line may also name an existing directory deeper than the units (apple/Persona/Views/Mail): it records a module's
# future home inside a core directory and is stale once that directory is gone.
#
# Moving a directory into a module root: delete its line here; the module-root line classifies the new place.
# Adding a unit: add one line, sorted with its neighbours. A unit that is obviously a module's future home gets the module id even while it still
# lives in a core path; that is what this file is for.
