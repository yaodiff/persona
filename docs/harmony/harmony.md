# HarmonyOS client

The [historical preview notice](prototype.html) explains that the earlier four-tab layout is retired. The current native implementation is in [harmony/](../../harmony/README.md), and this guide describes its behavior.

Persona's HarmonyOS client uses ArkTS and native ArkUI on HarmonyOS 7 / API 26. It runs on straight phones, conventional foldables and wide foldables; watches are outside this client. The Hub remains the only application backend. Agents run on the user's computers, with their existing runtime and host capabilities. For HarmonyOS 7 XiaoYi integration (On-Device A2A, Intents Kit, API 26 Skills, ShareKit, and the OpenClaw WebSocket bridge), see [docs/harmony/xiaoyi.md](xiaoyi.md).

## Product and information architecture

Persona and Agents are the two peer conversation views. Each keeps its own native navigation stack within the active Hub and manager scope. On compact phones, the header switches peers and opens the navigation drawer. Inbox and Settings are destinations in that drawer. Wide layouts retain the Spaces sheet.

- Persona contains the unique main chat, recent conversations and explicit new-chat flow, as well as Todos, Knowledge and the separate Health space. Recent lists the assistant’s five most recently active open conversations after its main chat and pinned directions are separated. All Chats’ Display Options menu and Assistant Profile share the Hub’s Show Scheduled Task Chats setting. Turning it on includes scheduled chats and the background supervisor in Recent.
- Agents uses the shared Rust core's iOS projection. By Status is the default; the existing grouping control also offers By Machine and By Project. Rows show friendly Hub/computer names and plain state words. On a phone, tapping the Agent chat title opens Session Info for that machine and session. The folder button beside its sibling tabs opens the workspace. The Agents menu opens Projects, where repositories and worktrees are grouped by computer. Search and the session workspace also retain repository and worktree identity. Search, state, computer, unread and history filters are explicit user actions; BackgroundWaiting is a separate quick filter. Pinned, quiet and folded groups, state/idle expansion and offline/history membership follow the core. Reading freezes membership and order while live status can update in place.
- The navigation drawer and Spaces sheet provide access to recent conversations and open Inbox, Todos, Knowledge, Health, Apps when available, Devices, full Settings and the active Hub. Settings separates device preferences from Hub/manager configuration.

On a compact phone, expand a repository and terminal tab to see its individual Agent panes. Selecting a pane opens its conversation. Orca and Paseo can supply repositories before a session starts. Other engines enter the Agent tree through their sessions. Their empty directories remain available in search and worktree management. Worktree actions use the selected computer and repository. After a rename loses its reply, checking the host name and explicitly choosing to keep it clears the local request so you can enter a new name. Cleanup shows the dirty-file preview and allows cancellation before removal.

A compact worktree opens a two-column Agent grid at both standard and accessibility text sizes. Windows narrower than 320 vp use one column. A conversation's More menu opens Files, Git or Terminal. The full-screen editor and the inline field share the current draft. Files keeps its search field visible, and a commit opens a per-file patch. Opening these tools from a conversation keeps the conversation title, project and sibling Agents in the header.

In Settings → Language, Dictation defaults to Automatic. It uses the draft and recent messages written by the owner of the current conversation to choose the input method. The user can also select on-device Simplified Chinese or the system keyboard. On-device recognition starts after microphone permission is granted. Stop recording, review the result and choose **Add to draft** before sending. Audio stays in memory. Changing conversations or backgrounding Persona ends the active capture. For other languages and devices without an offline recognizer, the same control opens the system keyboard for dictation. The compact drawer follows the system Reduce Motion preference.

On a compact phone, the conversation’s More menu opens Files, Git and Terminal. Back returns to the same conversation. Tapping its space title opens the Agent grid for that terminal space, including sessions in other checkouts in the same project. The machine chip opens that machine’s projects. Language and Agent settings keep the Settings sheet and the active search while the user moves between levels. The compact shell uses the same interface text-size limit as iPhone. Standard body labels grow from 17 to 23 while message text, file contents, minutes and the text being edited continue to use the selected accessibility size.

The assistant task bar includes the current assistant’s work, related Agents, pending decisions and completed work across conversations. Expanding a group lists the items behind its count. The To Decide entry above the composer opens one card at a time. The conversation’s own requests come first, followed by its tasks’ questions and approvals from oldest to newest. A request linked to several tasks appears once. Arrows and horizontal swipes change cards, and closing and reopening the pager preserves the current card and its unsent answers. A task’s card links back to its Agent. Plan approvals open a larger reader, and the card explains when a request cannot be skipped. A supported request can still be handed back to the computer’s terminal. Meeting participation is opt-in. An invited meeting uses its own Hub room, with recognized sentences and answers scoped to that room.

In an Agent conversation, pending permissions appear first. Other open requests follow from newest to oldest. The card stack scrolls above the composer. A follow-up goes to the current Agent session through its normal message queue. Each card keeps its own answer and request identity.

When the restored Persona stack is empty, the client looks up the Hub's existing main conversation with a read-only request. An offline, failed or empty lookup does not create a chat or change the selected conversation; the user can retry or explicitly choose New chat. This keeps opening the default destination free of creation side effects. A notification pushed over an existing conversation stack retains a child destination and Back; ordinary sidebar selection keeps its root identity and split-title behavior.

Inbox owns its filters, contextual source viewer, handled state, drafts and confirmed outbound actions. A Todo source reference opens that source conversation rather than fabricating an Inbox item. Management and conversation actions retain their captured Hub, manager, connection generation, route and target while asynchronous work completes; results from a retired owner or route cannot update or authorize the replacement context.

An extension that contributes a navigation page is also reachable from **Apps** in the native root navigation menu. Apps opens a native destination and a scrolling list, then the existing extension renderer; it does not add a primary tab for each extension. A successful empty directory and an older Hub without slot support leave that menu entry absent. Discovery failure offers Retry. The directory retains the Hub, manager, extension and contribution identities; cached rows do not authorize an action after disconnection, invalidation or an owner change. The page count is independent of the existing nested extension-navigation safety limit.

Conversation actions use a native title-menu item and an ArkUI Menu bound to the NavDestination. MenuItem rows have a minimum 48vp touch height; the platform owns popup placement, scrolling and dismissal. Choosing an action rechecks the captured conversation, route, owner and connection generation. The main Persona view and a split detail with its title hidden retain one native More button for those same actions. A blocking decision or read-only detail keeps that button outside the unavailable composer. Agent Filters and Rename bind their native sheets to distinct stable hosts, so one binding cannot replace the other. Transfer selection uses a scrolling native sheet with a fixed confirmation footer; its target List hands scrolling to the containing Scroll at either boundary. The sheet footer adds only the system inset that its measured content host still overlaps.

Chat content has no permanent Hub/computer/path subtitle. The selected navigation item, native title and explicit operation confirmations carry the necessary identity. Open editable questions show their actual prompt; pending, unknown and read-only states remain visible. A Persona transcript card has one Answer action that opens the native question sheet, without repeating its first question as an additional sheet subtitle.

Capability negotiation during reconnect retains disabled cached rows. An authoritative unsupported hello or successful empty directory removes the entry. Server-initiated stream closure immediately retires its page and triggers a directory read. Lifecycle operations also invalidate the directory; ordinary stream deltas and badges keep the page mounted. Since older install/enable routes do not always announce a directory event, an authenticated foreground connection with confirmed slot support rechecks every five seconds, including after an empty directory. Disconnection and disposal stop that poll.

Todos keep handing work to the assistant as the ordinary path. Manual New Agent is in the native More menu; its existing computer, directory and launcher form remains available on request.

The phone is a controller and reader, not another Agent runtime. A lack of a trusted online computer, a read-only source or a missing server feature must be represented before an action becomes available. An unavailable integration is distinct from an empty successful result.

Health always resolves the roster's default manager and explicitly uses `space=health`. Its conversations and records stay outside ordinary recent chats and the main chat. Reports go to that manager's trusted online assistant computer with `dest=health`; upload stages a path in a draft and never sends a chat turn by itself. HarmonyOS does not claim to provide Apple's HealthKit.

## Native layout and design contract

The structure comes from `Navigation`, `NavDestination`, native title controls, lists, selection controls, menus, sheets and dialogs. Reusable business views compose those controls; they do not draw replacement navigation, tabs, system pickers or dialogs. Persona supplies semantic colors, typography and spacing through resources and `Tokens`.

Navigation paints the active primary pane's background through its native bottom safe area: canvas for both peer lists. Scrollable controls remain inside the platform's safe bounds. A short list may leave unused space below its last row; do not stretch rows, remove system avoidance or add negative insets to fill it. The 4vp chat footer is a Persona spacing token, not a platform-defined gesture-area height. Question, plan-editor, context-selection and Spaces sheet content uses the normal 16vp inset, adding only any measured system overlap that the native host has not already avoided. The intrinsic-height Agent filter sheet uses 16vp side and bottom edges and an 8vp top edge, and compensates only its own measured overlap with the gesture area; a centered sheet adds no system inset.

Use an 8vp gap between separate chat controls and between the editor and action rows when the native GridRow wraps. In the compact row, reserve fixed action targets and 8vp gaps before assigning the remaining width to the same editor; do not round fixed buttons to twelfths of the row. Same-level feed cards share 16vp content edges with the composer. Latest is a quiet navigation action, distinct from Send. A title with no native Back control uses the normal leading content inset; titles with Back retain the platform's spacing. Spaces conversation rows use the sidebar's existing icon and text columns.

Appearance rows wrap the complete label and native Select, rather than squeezing short labels into one character per line. At enlarged text sizes, Inbox uses the same native Select fallback as Agents for status filtering. Context selection leaves wide-window sheet placement to ArkUI; short Agent filters use native content-fitting sheet height. Long content remains scrollable through the native sheet host. Title action menus bind to their native title button inside the NavDestination menu builder, rather than to the full page, so a detail menu stays beside its trigger in split windows.

Use the actual window class. XS, SM and MD use a stack; LG and XL use native split navigation. An expanded foldable can still have an MD window. Do not infer a split from a model name, screen pixels or a fixed percentage.

The expanded master pane starts at 320 vp, has a native drag range of 280–440 vp and can collapse to 64 vp. It contains the active peer's list; collapsing uses the native toolbar to restore the pane. There is no second navigation rail or permanent third pane. Persona and Agents share the title slot for a native symbol-only CapsuleSegmentButtonV2. The message and group symbols have independent localized accessible names; each item has a 48 vp minimum target. The same two symbols remain at large text sizes, without a text Select fallback.

Conversation detail hides its title only when the matching left-side selected row is visible and identifies it for the same owner. A compact window, collapsed pane, filter exclusion, offscreen selection or different owner restores the native title. File, history and other child destinations retain their own title and back action. Selecting another Agent replaces the Agent destination instead of creating a back stack of every selected row.

## Foldable and tri-fold adaptive workbench

HarmonyOS foldables (`Mate X7`) and tri-foldables (`Mate XT` / `Mate XT 2`) adapt via `FoldPosture.ts` and `NativeEnvironment.ets` using live `display.on('foldStatusChange')` / `display.on('foldDisplayModeChange')` callbacks, `display.getDefaultDisplaySync().densityPixels`, and `display.getCurrentFoldCreaseRegion()`.

- **Postures and multi-window bounds**: Narrow split-screen and floating windows (`< 560vp`) and 3-screen portrait (`~744×1061vp`) guard against cramming three columns: `< 560vp` stays in compact `'cover'` stack mode and `560–819vp` stays in `'dual_unfolded'` split mode even if hardware reports `FOLD_DISPLAY_MODE_GLOBAL_FULL`. Half-folded foldables at `>= 560vp` without a horizontal hover crease classify as `'book_half_open'` (`Foldable Book`), retaining dual-pane split and Live Workbench support. Unfolding past `820vp` (`trifold_unfolded` / `trifold_angled`) opens the 3-column Live Workbench (`Pulse` / `Code` / `Machines`) automatically, and secondary workspaces scale cleanly across 1-, 2-, and 3-column grids (`WorkspaceGrid.ts`).
- **Live Workbench quick controls, Quick Command Palette, & keyboard shortcuts**: `FoldInspectorPanel` highlights the oldest pending `Needs you` session at the top of `Pulse`, provides inline `Interrupt` actions on active `working` sessions (both live Hubs and local Demo mode), adapts its workspace action chips into a 2×2 Liquid Glass grid below `316vp` width, renders CPU % and normalized per-core load gauges in `Machines`, Done-Unread relay stepping (`Ctrl/Meta+[` / `]`), embedded `Code` (`Files` / `Git` / `Terminal` with a two-tier non-clipping compact breadcrumb header in `SessionTools`), `Machines` tabs (`Ctrl/Meta+1/2/3`), and a quick `XiaoYi` entry (`Ctrl/Meta+0`). The Quick Command Palette (`QuickCommandPalette.ts` / `QuickCommandSheet.ets`, opened via `shell.quick.palette` or `Ctrl/Meta+K`) provides instant keyboard-driven navigation across urgent/active agents, visible workspaces, Live Workbench tabs, XiaoYi, LiveView preview, and immediate Light/Dark theme toggling.
- **Crease-aware Hover Tabletop**: When a half-folded posture supplies a valid horizontal crease band (`resolveHoverSplitGeometry`), the active `Navigation` reading surface renders strictly above the hinge crease and a dedicated Tabletop Control Deck renders below it with relay controls and quick launchers.

Navigation owns the main page's system avoidance. Main content adds only the 4 vp business footer gap; it does not copy the system gesture-area height into bottom padding or add another safe-area spacer. A bottom sheet measures its content host against the current system avoidance boundary and adds only the still-overlapping amount after layout. A centered sheet or already-avoided host adds no extra system inset. Recompute that overlap when the host size or native safe-area value changes; never use a fixed inset or repeat it on inner rows. List tail clearance must not reserve space for a removed bottom bar.

The conversation uses `FoldSplitContainer` for horizontal half-fold hover. Reading stays in its primary region; the current decision or composer stays in its secondary region. The native component owns crease avoidance. It is instantiated only when the system supplies valid fold-crease geometry. A foldable emulator image that omits that geometry uses the ordinary native Column and Scroll layout; it cannot validate hinge avoidance or hover behavior. The capability is sampled when a conversation view is created; configuration callbacks do not switch that view between native subtrees, preserving input composition, focus and transcript identity. This capability check prevents the framework from dereferencing an absent crease region and does not invent a hinge or emulate hover. Outside hover, the measured content height determines the ordinary split, so a phone does not inherit a fixed 50/50 division. The interaction region scrolls when large text, expanded choices or the keyboard reduce its available height. The transcript scroller and draft owner remain the same across posture changes.

Appearance has separate pages for the message color, interface style, navigation, Agents list layout, and light or dark appearance. Returning to Settings restores the search that opened the page. Liquid Glass, Clay, Island, Lark and BeautifulUI apply to the current conversation and survive a restart. New installations can follow System, and previously saved Brief or Board choices retain their settings. The selected Agents tab also opens the four list layouts. Choosing one updates the directory and the Settings preview together.

Avatar and Accent are independent device preferences. Native list groups, Radio and Select controls expose the built-in avatar, authenticated Hub packages and accent choices. Initialization restores the saved preference before enabling changes, including a retry after storage failure. Each package choice retains its source Hub and revision, so identical package IDs from different Hubs remain distinct. The selected image is an intentional device preference and survives Forget Hub; other cached images from that Hub are purged. A new preference is published only after storage acknowledges it.

Use the native design roles and tokens rather than local numeric or color literals. In the System style, the light primary action uses emphasized blue (`#0071E3`) with white on-action text, text links use `#0064C8`, and own-message bubbles use `#DCEAFF` in light appearance and `#1D3557` in dark appearance. Needs-you is `#0064C8` / `#86B6FF`, working is `#9B5500` / `#FFB224`, unread is `#1D7A4C` / `#4CC38A`, and positive is `#237337` / `#30D158` in light / dark appearance. These are separate semantic roles with a visible state label or symbol as well as color; do not use status colors as generic warning, success or brand colors.

The standard typography is the HarmonyOS system font at 20 fp for titles, 17 fp for body text, 14 fp for secondary text and 13 fp for captions, with a 24 fp body line height. The app follows the system font scale through its supported 3.2× maximum. Explicit custom colors are resolved from ArkUI `onWillApplyTheme`; global system resource IDs do not substitute for a scoped theme. Shared spacing uses 16 vp page margins, 12 vp insets, 8 vp gaps, 24 vp section spacing, 20 vp business-surface corners and a 4 vp content footer. Interactive controls retain at least a 48 vp response area; native controls own their internal sizing and material.

Native `WithTheme` supplies light and dark brand/emphasis tokens and readable own-message tokens without tracking system color mode in a second observer. Package PNGs have separate encoded-size and decoded-dimension limits, must pass native image decoding, and are installed atomically in private storage. Semantic text and bubble contrast is at least 4.5:1. The application opts in to the platform's UIMaterial behavior; supported native controls own the material effect and its system fallback.

The device-level Agent row density is Standard by default, including when an older saved preference has no density field; Compact is an explicit reversible choice. Density is committed with the complete device appearance record so Avatar and Accent values are preserved. Agent grouping follows iOS: By Status by default, with By Machine and By Project as explicit reversible choices in the filter sheet and Appearance. Older flat/repository/worktree preferences resolve to By Status rather than retaining platform-specific grouping semantics. Machine identity includes its Hub group and manager when supplied, so two managers sharing one machine ID have independent groups and filters. Group fold, idle expansion and quiet-space expansion are stored in the same owner-scoped `agent-workspace` view as the filters, not in device appearance. Archived history may include offline snapshots only when explicitly enabled; their group and current fold state still apply, so folded groups keep archived members for counts and later expansion instead of displaying them early. The shared Rust core is the only production sorter; no duplicate ArkTS sorter or debug shadow remains. Native core failure retains the last usable list and reports failure rather than presenting an empty successful result.

Persistent sidebar and Spaces labels resolve their translation inside the rendered native row, so an in-app language switch updates them alongside destination titles without rebuilding navigation or losing drafts. Do not add descriptive subtitles, explanatory child controls or a second action for the same purpose. Target identity belongs where a decision needs it. Operational errors and confirmations state the actual target or consequence. A title already supplied by the destination is not repeated in its content. Long actions move to native menus; controls must remain usable with large text and the keyboard visible. Plan machine, working-directory and permission metadata use native wrapping Flex, so read-only status remains visible before starting. Inbox search takes its own line at enlarged system text sizes; native functional actions retain 48vp icon targets and wrap as complete controls when needed. Source/account Select controls share an equally divided native Row at standard text sizes and use full-width native Column rows with enlarged text, preserving the same page edges and giving enlarged labels the full available width. Avatar/Accent labels and selectors wrap instead of competing for a fixed row. The fixed-width native symbol peer segment keeps two 48vp targets at every text scale; its localized accessible names identify both views. New and Spaces keep their reserved touch areas. The application configuration explicitly follows the system font scale, including its 3.2× maximum; ArkUI uses `fp` for text.

## Conversation and operation lifecycle

A detail context captures its Hub, manager, machine and session. Opening a manager-owned resource does not change the workspace's selected manager. Global Settings remain workspace-owned; settings opened from a chat retain that chat's target. Chat readiness also retains the resolved client owner, scope and selected-row identity. A selection change invalidates the old chat destination immediately, including while a newly created chat is still loading. Same-owner reconnects keep that readable page and its native picker mounted; generation belongs to the individual network-send admission. Resource pages remain mounted while their handoff selects the destination chat. Delayed composer callbacks recheck the active, mounted route before preparing a send and after draft, outbox and mutation journaling; a retired route cannot authorize a new POST. File-upload admission is also rechecked after its mutation journal. An already dispatched operation still settles its captured receipt.

The composer keeps one native `TextArea` and one draft owner as the pane width, system font scale, focus, draft length and attachments change its GridRow spans and order. Resizing does not replace the editor with a second input node. Context chosen from Knowledge, Todos or Inbox is staged on the current chat draft and is sent only with an explicit message submission. Context picking and Knowledge handoff share the same legacy-reference promotion: the complete quoted source object, including text and any metadata, is retained alongside new references. Photo and file attachments retain their separate local draft owner. Every asynchronous lookup and action rechecks the captured Hub, manager, connection generation, route and target before updating or sending. IME composition continuity across resize and posture changes remains a device acceptance check; layout structure alone does not prove it.

When a focused composer is activated by touch, Attach and More use the native ArkUI Popup with a non-focusable, masked native List, leaving the editor in place while the rows remain touch-operable. On the tested API26 phone emulator, opening either popup and dismissing it by touching the mask preserved the original uncommitted candidate; the application neither committed nor reconstructed that text. System Back retains the platform's keyboard behavior: on that emulator it closed the popup and keyboard and removed the candidate on both tested layouts. Do not claim candidate retention for this path or replace native Back handling to imply a guarantee the framework does not provide. The committed draft remains application-owned. Other activation sources, including hardware keyboard and accessibility activation, use the native Menu and its platform focus behavior. Popup content is built lazily by the overlay, never in the editor's GridCol. Placement uses the measured editor rectangle and available window space; row and divider measurements bound a scrollable list at large text sizes. The same captured owner, target, connection generation and action revision gate every callback, including dismissal and host removal.

Choosing an external photo/file picker or opening a context-search sheet intentionally starts another native focus session. The application preserves the committed draft across those journeys; it does not synthesize or restore a retired input method's candidate list. Composition continuity must be demonstrated with actual on-screen input and selection of the original candidate, rather than injected ASCII keycodes.

Transcript rows use native Repeat virtual scrolling and stable item keys so List can retain visible content during history prepends. Lazy loading stays enabled; cross-message node pooling is disabled because message, image and action subtrees have distinct lifetimes. Changed Markdown blocks have content-derived identities so a streamed paragraph cannot retain a previous block snapshot. Message, question and context-menu builders receive the complete observable RepeatItem; their row properties and event callbacks read the current item rather than a value captured before native reuse. A detached long-press menu instead captures its message when the native overlay opens, so a recycled slot cannot retarget an already presented action. Explicit Load more captures a visible content row before the first loading control can disappear, then restores its surviving ID and offset once with the native Scroller after both advertised history sources settle. A visibility loss, owner change or user scroll retires that restore; a same-session directory refresh does not. Ordinary incoming rows continue to use native List position preservation. Validate both the row ID and its actual displayed text and action target after scrolling or inserting history.

In Persona assistant conversations, including secondary chats, `ask_user` cards live in the transcript while the same composer stays available for additional messages. Each pending card owns its interaction ID and request snapshot. Sending a message does not resolve a card locally: the Hub withdraws an ordinary waiting question, while a `wait:false` question remains answerable. Multiple cards can be answered independently. Answer opens one native large sheet with a scrolling question body and a fixed native wrapping footer containing Later, the native More menu and Confirm. Explicit Cancel question is inside More when the Hub permits it. The sheet uses native resize-only keyboard avoidance and uses a 16vp internal inset plus only measured residual system overlap. Closing or choosing Later sends no operation and retains answers for the same owner, conversation and immutable interaction snapshot. A changed request or owner retires that draft; reopening an identical request restores it. Answer admission is checked again after the durable journal write and before transport, so a retired sheet cannot dispatch. A refused admission restores Open only for that same still-pending request; a newer resolved, closed or unknown status is preserved. The chat composer remains the same node behind the sheet. Agent questions, permissions, plans and unknown tools retain their blocking and approval rules. Their blocking form uses half the ordinary conversation height, preserving readable chat context; while the native docked keyboard reports a positive height it may use the remaining conversation height to keep the current input and response actions reachable. Native hover still owns the physical hinge allocation. Questions use a scrollable body and a native wrapping Cancel/Confirm footer; multi-action elicitation keeps its body and response controls in one native Scroll so a short keyboard viewport cannot strand a last action. A second outer Scroll and estimated button heights do not clip the decision controls. Unlike the deferrable Persona sheet, this layout adds no Later action; an assistant question cannot hide another pending approval.

Recovery does not interpret a missing local card as permission to act. Send and answer admission wait for a successful interaction read for the current connection and target. A delayed or failed read keeps the draft editable and cannot unlock a previous blocking request; a successful empty read can clear it.

Assistant plan and receipt cards keep a short inline summary and open a native detail destination for the selected item. The destination locates the exact item by reading the captured conversation's feed from its head through successive cursors; it does not treat the initial page limit as proof that an older item is missing. Cursor loops, read errors, a changed source or a retired owner stay unavailable and recover through an explicit retry. A cached plan can remain readable, but start, edit and dismiss require a fresh plan read and the existing Hub admission rules.

Receipts use the Hub's `done`, `failed` and `interrupted` outcomes. `stopped` is derived only when a successful Todo read confirms that the associated Todo remains open; if that read fails, the outcome is unknown. The detail shows the actual summary, error, pull request and criteria. Only criteria marked `met` count as passed; `not_met`, `unchecked` and `dropped` stay distinct, and the number of additional criteria is not a pass result. A done or stopped receipt offers no continue action. Retry requires an eligible failed-start Todo and current write capability. Continue requires an incomplete Todo, an eligible lead Agent and current write capability; suppress it during active automatic recovery. Both actions recheck their current facts when activated. A missing or mismatched recovery Todo acknowledgment is recorded as an unknown result in the shared durable operation journal before completion; reopening a detail or restoring storage cannot silently send a replacement. The server may omit the Todo manager; when present, it must be a string matching the captured owner. The client then reads the receipt and Todo afresh, independently of an older in-flight feed refresh. The existing operation-status check is required before releasing an unresolved attempt.

Each chat draft has a revision. A submitted message is persisted in the local outbox before network admission and appears immediately. Its stable `client_msg_id`, rather than matching text, reconciles a server echo. The outbox uses an index plus individual bounded rows, not one growing database cursor row. The operation journal contains identity and outcome, not another copy of message text or photo Base64.

A known acknowledgement clears only the captured draft revision. Newer edits survive, including identical text typed again. An unknown result blocks that destination until it is reconciled; another chat can still send. Reconnection never silently creates a replacement operation. Explicit confirmation of a local-only crash window may release it only after the server's receipt lookup proves there is no recorded operation.

Attachments remain local until explicit Send. Native photo/document pickers grant access to the user's selected files; sandbox copies have bounded size and validated decoded image content. A system photo editor receives read permission and returns a new selected attachment, preserving the original. System preview provides image zoom and supported PDF, Office, HTML and media viewing.

The photo picker uses the remaining picture count for this chat's Agent. Older hubs use the protocol defaults of 20 pictures,
a 1600 px long side and a 32 MiB message body. Photos that exceed the count or the encoded message budget go to the session's
computer as files. The chat tells the sender which limit was reached. Documents and videos keep their separate file slots.

Received images open an authenticated conversation-scoped system gallery. Editing one stages a new outgoing image in that conversation's draft. A native editor may pause the application and cause a reconnect; the stable pairing revision, Hub, manager and draft identity determine whether its result still belongs there. Forgetting, re-pairing or changing the destination rejects the result. An acknowledged draft keeps its referenced file even if navigation occurs while storage acknowledgement is returning.

An outbox message carries only the selected attachment IDs and revisions for cleanup. HTTP acknowledgement, exact echo or a later receipt suppresses those revisions before fallible I/O. Failed cleanup keeps a durable obligation and blocks reuse; ordinary terminal-history pruning cannot discard it. Local storage epochs fence queued work across Forget Hub and immediate re-pairing. Successful cleanup preserves newer unsent attachment revisions.

Native picker pauses and same-owner reconnects do not detach the local attachment selection. Hidden pages stop their subscriptions and release terminal/audio/screen control. Foregrounding rebinds the captured resource to the new authenticated repository and re-fetches current facts; it does not replay mutations.

## Workspace, source and permission boundaries

Files and Git use the existing machine routes. Writes, branch switches, stash operations and push require a native confirmation with computer, directory, branch and operation. The client does not automatically force-push, clean or reset. Acknowledgement remains success if a follow-up read fails. Conflicts keep the user's draft.

The file menu's **Send to computer** sends a normal file directly between two online, trusted computers belonging to the same manager. Native target selection shows the target's receive folder and the two computers' transfer switches. Each switch defaults to off and can be turned back off. A rejected setting change preserves the last confirmed value; a lost response makes the setting unknown until a fresh query confirms it. The client does not issue a compensating write or treat an unknown setting as authorization. Reopening a panel waits for in-flight setting writes for that manager and computer; another retained view loses its old setting authorization immediately. A late read cannot restore a stale enabled value.

Each switch names its computer and controls that computer's shared sending/receiving permission. Choosing the source computer as the destination displays that setting once. Creation, progress and terminal state publish through an observed journal mirror so the first task becomes visible immediately. A page retired by an extension change discards its old rendered form and loaded code context; a fresh authoritative read is required before it becomes interactive again, while ordinary unsent drafts and captured write receipts retain their separate lifetimes.

The file workspace uses native composed list items and labeled icon controls, with scrollable tabs and automatic tab-bar height. Transfer file names, computer names and paths wrap in native scrolling content. Footer icon actions retain 48vp targets and move onto separate rows if the available width requires it. A capability arriving after route restoration can enable the transfer entry for that captured connection; removing it revokes the entry immediately. Target rows retain observed identities within the same owner so a computer rename updates an already displayed chooser.

The manager relays the file; the phone never downloads and uploads its bytes. The dedicated transfer journal records creation before dispatch. HTTP 202 and a task ID mean accepted/running, not completed; only `done` means the file arrived. Progress and cancellation use that captured ID. A failed follow-up query does not erase an accepted task, and cancellation is shown only after its actual outcome is known. A lost creation response without an ID remains unknown: this protocol has no collection or request-ID lookup. Checking that local record does not claim success or resend; another attempt requires a new explicit confirmation. Reconnection queries known IDs and never creates a replacement. A missing task after a manager restart also remains unknown. A terminal outcome already acknowledged by an event survives a late failed read. Reopening an active task shows its captured target computer and receive folder without authorizing a new target.

Workspace → Preview lists the selected computer's existing development servers and opens their authenticated remote browser preview. Navigation and input belong to that captured preview session. Hiding, disconnecting or replacing the workspace releases its browser stream; it does not silently restart a development server or replay input. This is separate from opening conversation links and from local document preview.

Terminal viewing begins read-only. Taking control is explicit and revocable; hidden, disconnected or replaced contexts cannot replay queued keys. The desktop RFB screen is a separate capability from a terminal's text screen. It uses the authenticated native binary WebSocket transport to the Hub's existing port relay, with read-only viewing and separately confirmed control.

Source-specific Inbox actions preserve manager, source, account, conversation and message identity. Reading acknowledges only visible content. Outbound replies show their actual account and recipient before confirmation. Native Todo references use the source-message endpoint to locate a conversation position; a topic binding is not treated as a message ID.

The current Todo contract can contain a Feishu `omt_*` thread binding without a root `om_*` message. The messaging API opens a thread by root message ID and exposes no verified mapping from that binding. Such a binding remains readable metadata with no fabricated read/reply operation. An explicit verified root message can use the existing thread API. This is a server/provider contract boundary, not a client-side ID conversion.

Phone tools request their own platform permission when used. Permission to read is not permission to write; writes require a phone-side confirmation and expire without approval. Unsupported platform data capabilities have an explicit result. Voice uses its negotiated extension protocol and releases audio resources on interruption/background; lack of a configured voice service does not prevent text use.

Contact writes require separate read and write permissions, show the before/after values, and recheck the original contact immediately before updating only requested fields. Calendar operations use calendars accessible to the application. Updating or deleting a recurring occurrence or splitting a series is unavailable with the current atomic Calendar Kit contract; the client does not substitute a whole-series mutation. Access to all system calendars requires the separately qualified whole-calendar permissions. Place-name search uses geocoding and does not read the phone's physical position.

Voice chooses the highest protocol version this client implements from the extension's advertised maximum. Legacy V1 is restricted to the manager's unique main conversation; it cannot target an Agent or a secondary conversation. V2 binds its ready frame and audio stream to the selected machine/session. Permission dialogs, reconnects and pending capability discovery cannot change the protocol or target of an admitted call.

Knowledge recordings keep bounded PCM audio in the application sandbox. For a local recording, stopping capture, transcribing and syncing are separate actions. The device queries Core Speech for its available recognition languages. The API 26 Mandarin recognizer takes mono PCM16 at 16 kHz. Feeding begins after the matching recognition session reports `onStart` and ends on cancellation, error or early completion. A user-confirmed Knowledge sync sends transcript segments and metadata. An uncertain acknowledgement retains the recording ID, revision and body for an explicit retry. Backgrounding retires capture and recognition. Forget Hub removes that Hub’s locally stored recordings.

A meeting can use the device or a configured Hub transcription service. Before starting, the confirmation names the selected service and where the audio and transcript go. A per-meeting choice leaves the saved default in Settings intact. A confirmed Hub meeting sends audio on the authenticated recording stream and shows the current caption source. It resumes at the offset the Hub acknowledges after an interruption. If the service reports a problem, the meeting uses the device’s available captions. The unmetered-only preference checks the active network before opening the audio stream and while it is in use. A local or private meeting keeps its audio on the device.

Scheduled task templates populate an editable draft and do not create a task until confirmation. Run Now opens only the acknowledged response's actual machine/session; failed or uncertain new attempts cannot reuse an earlier result. History entries without both destination IDs remain readable without an invented conversation link.

## Architecture

| Layer | Responsibility |
| --- | --- |
| `harmony/entry/src/main/ets/core` | Pure protocol reducers, transcript continuity, capability policy, bounded content parsing and frame/selection logic |
| `models/ClientModel.ets` | Workspace and detached manager contexts, catalog, selected chat, draft/outbox and lifecycle coordination |
| `models/HubRepository.ets` | Existing REST contracts and durable mutation admission/receipts |
| Dedicated workspace models | Todo, Knowledge, Health, Inbox, Agent list, file/Git/terminal and management state with captured owner guards |
| `platform/HubTransport.ets` | Native HTTPS/TLS and WebSocket transport, endpoint validation, pin verification and bounded frames/bodies |
| `platform/LocalStore.ets` | App-sandbox relational storage, serialized writes and per-Hub retirement epochs |
| `platform/CredentialVault.ets` | Platform Asset Store credentials, separate from application data |
| `models/SshTunnel.ets`, `platform/SshCredentialVault.ets`, `native/ssh` | Conditional pinned SSH connection, authenticated local proxies, bounded device-only private-key storage and native cancellation |
| `components` and `pages/Index.ets` | Native business views and navigation, localized resources and platform controls |

The secure endpoint and identity are fixed before sending credentials. A supplied pin does not fall back to ordinary CA trust after a mismatch. Paths cannot escape the authenticated origin/prefix. Redirects do not transfer authorization to another origin. Binary downloads, JSON bodies, frame assembly, decoded images and local cached content have separate bounds.

Forgetting a Hub retires its operation contexts before removing credentials, scoped database rows and owned file/cache copies. A durable cleanup record is acknowledged before physical erasure starts. Failed cleanup keeps that identity after the profile disappears, blocks reconnection/re-pairing to it and retries at startup, foregrounding or the explicit Retry cleanup action. Clearing the record requires every cleanup step and the profile update to succeed. Retrying another Hub's cleanup does not stop the active Hub's SSH lease. Device appearance remains local. Runtime secrets, paired URLs, generated signing material and private fixture records never enter the repository.

Phone-tool registration and incoming calls belong to the same captured client context. Changing the active phone/voice settings owner removes the old subscription and advertises an empty tool list on its old connection before registering the new owner. Late events cannot be assigned to a different Hub. Returning from contextual settings restores the workspace owner. Old audio resources detach their captured listeners before asynchronous release, so their cleanup cannot consume or clear a newer call.

HTTP `Accept-Language` and WebSocket `client_hello.locale` use the effective application language, resolved to `en`, `zh-Hans` or `ja`. A successful explicit language change re-announces capabilities on every live workspace and detached manager connection. Native Follow system takes effect after a cold application launch; selecting it keeps the current launch's UI and wire language aligned until then. Recreating an Ability in the same process does not apply that pending change. Matching-system mode re-announces after a system configuration change; unsupported system languages resolve to English. A failed preference write restores the prior visible and wire language.

## Build and identity

Open `harmony/` in DevEco Studio with the HarmonyOS 7 SDK, or use DevEco CLI from that directory. API 26 is the supported minimum and target; older API compatibility requires a separate component and device matrix. The repository supplies a development example bundle identity. Maintainers supply the registered identity and signing configuration privately before distributing a release; this guide does not authorize store upload or submission.

Build the locked ARM64 SSH core before the HAP, following [the native build and license instructions](../../harmony/native/ssh/README.md). It requires Rust 1.98.0 with the OHOS target and the API 26 native SDK. CMake packages both the NAPI bridge and its core library; generated binaries stay outside version control. Private keys use bounded 1 KiB Asset Store chunks and a final manifest, with device-unlocked access and synchronization disabled. The database stores metadata and a random key reference only.

Direct Hub WebSockets resolve names on the current network. They try IPv6 first and alternate available families within one connection deadline. The connected TCP socket then starts TLS using the paired hostname. A certificate or pin failure ends the connection before the WebSocket upgrade sends credentials. Main and child streams use the same procedure.

SSH accepts only the captured SHA-256 host-key fingerprint before authentication. Its local authenticated proxies admit the captured Hub host/port only. Device DNS answers can admit a TLS socket's resolved IP to SOCKS, but the SSH channel still opens the logical Hub hostname; HTTPS Host, SNI, SPKI and base-path checks retain that original identity. Backgrounding, owner changes and cancellation retire the same lease for HTTP and child streams. Asset removal queries bounded attribute-only pages by profile/reference, then deletes exact aliases; it never retrieves secret values for cleanup. This also accommodates API 26 runtimes that reject critical labels in `asset.remove`.

The locked dependency notice inventory is bundled as a local application resource. Privacy → Open source licenses opens its complete texts offline in a native sheet, using ArkWeb with JavaScript, DOM storage and file access disabled. `harmony/native/ssh/package-notices.py` verifies every inventory checksum against the retained notice and the locked package identities before generating that resource.

The app and entry Ability refer to the same layered image. The 1024-square source foreground reuses Persona's approved artwork, the background is opaque and flat, and the startup image uses the approved flat icon. `harmony/scripts/export-icons.py` generates the resources and `harmony/icon-manifest.json`. SDK resource compilation can legitimately convert the icon layers to 512-square RGBA PNGs; inspect the packaged content and references rather than treating that size as a source-art rule.

The session menu offers the model when the session advertises model switching, and reasoning effort when it lists available levels. A terminal Codex can offer both with no permission-mode control. A runtime that reports a fixed model can still offer effort. The model page uses the session's named launcher on its computer, or Codex for a manually started Codex pane. Saving sends the selected model ID or effort to that session's modes endpoint. Demo and offline sessions do not dispatch these changes.

The native composer stacks input, Send and Attach at an effective application font scale of 1.5 or higher, and in narrower panes. Chinese and Japanese attachment labels stay concise. Grid span/order changes retain the same input node and draft; verify native IME composition continuity on device rather than infer it from this layout behavior. Functional actions use fixed-size native icons with localized accessible names; content choices retain visible labels. An active interruptible turn offers Stop in place of an empty Send; a prepared message retains Send and exposes Stop once in More. Effort appears only in More for an Agent that advertises modes and actual effort choices; per-purpose model settings remain in Settings.

## Verification

The commands and matrix below are reusable procedures, not a report that a production regression run has passed. Record the actual test output, HAP build identity, measured window classes and native captures for each run. A prototype or portable test alone does not prove the production HAP, a real Hub exchange, a live Codex or other Agent runtime, a physical hinge, or device system-material behavior.

Environment prerequisites: portable tests need Node.js 24 or newer. HAP builds need the HarmonyOS API 26 SDK, DevEco CLI and the pinned OHPM dependencies; building the bundled SSH core also needs Rust 1.98.0, its OHOS target and the API 26 native SDK. Native test execution needs an owned API 26 emulator or device with `hdc` access. Real Hub journeys need an isolated Hub and synthetic work. Physical hinge, system-material and IME-composition checks need a device or system image that exposes the corresponding capability.

Run portable behavior tests with Node.js 24 or newer from `harmony/`:

```sh
node --test tests/*.test.mjs
node tests/run-domain.mjs
```

Build the application and the native SDK test target separately:

```sh
devecocli build
devecocli build --modules entry@ohosTest
```

Install the test HAP on an owned emulator and run its Stage test runner:

```sh
hdc -t '<device serial>' install entry/build/default/outputs/ohosTest/entry-ohosTest-unsigned.hap
hdc -t '<device serial>' shell aa test -b '<development bundle>' -m entry_test -s unittest OpenHarmonyTestRunner -w 60
```

The tests use unique database names and owned aliases/copies. They must not erase a normal profile. Native transport tests additionally use the local fixture in `harmony/tests/native-transport-fixture.py`; its last case rotates its own certificate, so restart only that fixture before another run. Do not rotate a paired Hub certificate as test setup. The `previewCheck` test argument enables the image preview suite. Reopen the main Ability after a test run before taking UI evidence. The optional `fontScale` argument (`1.75`, `2` or `3.2`, with `aa test -s timeout 60000 -w 90`) opens the actual application at that verified native scale for a 45-second layout inspection, then restores its original application scale. For a longer scripted journey, `fontHoldSeconds` accepts 15–120 seconds; use a matching runner timeout, for example `-s fontHoldSeconds 120 -s timeout 150000 -w 180`. This probe is confined to the test HAP and does not change system font preferences.

Keep one owner and one active run per build/test. A worker writing a module does not run a competing build. Portable tests verify behavior with platform boundaries stubbed; they do not replace native SDK results or device screenshots.

To exercise an AAAA-only Hub name on an owned emulator, start the native transport fixture on host loopback port 38665. Read the public `pin` from its generated `fixture.json`. With the application and test HAP installed, run:

```sh
hdc -t '<device serial>' rport tcp:38665 tcp:38665
hdc -t '<device serial>' shell aa test -b '<development bundle>' -m entry_test -s unittest OpenHarmonyTestRunner -s ipv6FixturePort 38664 -s ipv6ForwardPort 38665 -s fixturePin '<fixture pin>' -s timeout 40000 -w 140
hdc -t '<device serial>' rport rm tcp:38665 tcp:38665
```

The test application listens on IPv6 loopback and forwards the TLS bytes to the fixture. It maps the reserved name `hub-v6.test` to IPv6 loopback with an application-scoped DNS rule and removes the rule afterward. The fixture reports the HTTP Host, SNI and request path inside each WebSocket hello. This checks the literal control, the DNS name on the main and child sockets, and rejection of an incorrect pin.

## Compact native actions

The selected Assistant menu and the Inbox menu both open Background Activity for the main conversation. A completed silent round retains its original input, tool messages, dispatched tasks and assistant answers. Opening the sheet leaves the conversation's read position intact. Expanding work reads the folded output. A task reference opens its detail, and a dispatched Agent becomes the destination when the sheet closes.

The main conversation's Needs You tray shows questions, elicitation requests, owner-proposal permissions and decisions that reach the user. A plan and ordinary Agent permissions remain accessible from their own conversations. All opens the current conversation's task board, including finished tasks.

A briefing’s In Progress and To Verify rows open the task. Waiting for You and Can Wait can open the Agent conversation named by the card. A recommendation or acceptance acts on the review round shown in that briefing. Handled acknowledges the queued question. When the workflow’s stage names exceed the available width, the dots stay visible and a line gives the current stage and its position.

Project search keeps the selected machine and includes terminal sessions. Needs You counts each session once even when that Agent has several pending cards. Changing the grouping in Agents preserves the active search.

A failed task can be opened from its task list, the main conversation or its task board. When the Hub supplies a current startup question, choose one of its offered responses to continue the original attempt. The retry and remove actions reflect whether the task already had an Agent. On the to-do list, Got It files an eligible result and Undo returns it to the list.

Assistant serves everyday conversation and tasks; Agents retains specialist controls. Both use the shared semantic roles from iOS through ArkUI resources. The sidebar and content share the canvas, selected native rows identify the current context, and AI/Knowledge and Health have distinct module icon colors. Color supplements a symbol or visible state; it never creates an execution result.

`IconActions` defines known action symbols and progress states. `ButtonStyles.icon` and `iconPrimary` use actual 48 × 48 vp native Circle buttons, 22 vp symbols and shared foreground/background roles. Existing title tools retain their 40 vp visual and 48 vp response region. Start is Play, Send is Up, Save is Check, and Retry is Refresh. Body editing uses the functional size. Labels remain for content, real choices, file names, keyboard keys, Git diff scope and system confirmations; these are not wide action slabs. Avoid descriptive subtitles and duplicate View/Details actions when the content row already opens the destination.

A question has one trailing Answer icon. A plan uses the canvas, separates its execution context, goal, excluded work and completion conditions, and keeps Edit/More and trailing Start without repeating a detail title in a visibly selected split context. Non-message conversation cards have 16 vp outer edges; message and composer insets are not doubled. Todo groups use native row dividers. Short filter sheets align native labels and Select controls. Sheet editors reuse the system close action rather than adding a duplicate Cancel footer.

Permission and plan decisions retain visible Allow/Approve and Deny choices. The submit symbol follows that choice: shield for approval, red prohibition for denial, neutral Check for other confirmations. A valid Stop remains the primary chat action. Sending/waiting uses native progress; an uncertain result uses a warning and cannot become a new send. Accessible names describe the same action/state as the glyph. Attachment removal includes its file name, and attachment upload sits by that file with a document-upload symbol, distinct from text Send.

Unknown extension actions use one native, named menu per container, including review/composer actions, comment actions and each diff context boundary. Menu callbacks capture the model, presentation identity and visibility generation; they read the current bound fields only after that identity is admitted. Diff ranges additionally retain their file/side/range identity and retire obsolete entries. A danger tone changes visual color; only an explicit destructive role adds that permission role, and the action's own confirmation is preserved.

Inbox item writes share synchronous admission across replies, attachments, handoff and Process/Reopen. Preparation before account lookup or journal admission is known unsent; the repository's final admission callback rechecks the captured owner immediately before transport. A disconnect makes known-unsent work retryable and dispatched work uncertain. Attachment reply targets are frozen before asynchronous lookup. Pending/unknown receipts, malformed attachment acknowledgements and replies naming another item retain no-resend protection; Reply, Process/Reopen and handoff receipts require a matching nonempty entry ID before the journal records success; handoffs require the item envelope. A confirmed handoff without a session can read back its navigation target without redispatching the write. Confirmed success does not become a retryable failure when later local cleanup fails. ## Native data updates

When a different worktree has an unresolved rename, the phone can check its original request and the current host inventory. If the original workspace has been removed and the current workspace is uniquely identified, the rename form offers to close the old local record. Confirming rechecks both identities and preserves the old request. The current name is submitted only when the user confirms the new form.

ArkUI `ForEach` retains the item generator for an unchanged key. The dynamic Persona, Agent, Inbox, Todo, Knowledge and Health lists, management rows/fields and file/Git/preview rows use renderer-owned `BoundRow` references to keep a stable native key within one model owner and scope while their traced value follows the latest immutable model row. Deferred menus and click handlers read that current value. A new owner or scope receives new native keys; source rows remain immutable because resource admission uses their snapshot identity. Reconciliation indexes identities and duplicate occurrences with maps. Agents freeze list membership only after their saved view and initial rows have loaded; opening a detail during initialization must not freeze a temporary empty list.

Extension JSON is copied into a bounded `UIUtils.makeObserved` presentation tree. Same-page updates retain interactive nodes and draft focus; changing page, model owner or snapshot epoch replaces the presentation generation. Array reconciliation follows the renderer's actual keys, and read-only primitive leaves use content keys. Builder arguments that can change are native bindings, including action values read at the time of a click. Section positions remain live when keyed sections move. Derived chart rows read observable arrays through explicit indices; native update evidence must cover nested values as well as top-level text.

Native buttons retain framework foreground/background pairing and semantic roles. Do not put the brand foreground color on the framework's filled primary background; it can make the caption disappear. Extension MenuItems use error color for an explicit destructive role or a danger tone. Only the explicit destructive role is passed into the existing confirmation/admission flow.

A streamed action with a confirmation completes the Hub's own permission gate only after the user has confirmed the exact frozen action. The host interaction must match the current manager, page session, epoch, version, saved action and summary, have no input or secret fields, and remain unexpired. Dispatch rechecks ownership and visibility; this never grants generic Agent approval. A restored route can start before the socket hello advertises stream support, so capability arrival retries the stream read and retires the older HTTP read. Falling back to a legacy view preserves its unsent fields.

Inbox lists re-read their aggregate endpoint when the owning client receives an inbox update or a child operation is acknowledged. They do not substitute the client's owner-filtered inbox cache for the aggregate list. A separate list request sequence rejects late rows, source metadata, errors and loading changes without resetting page identity, filters or compose drafts. Todo and Knowledge parent lists also re-read when revealed after a child mutation; reconnect recovery completes interrupted detail initialization while preserving newer local editor input. Acknowledged writes invalidate older reads before they can restore pre-write values.

Environment prerequisites and physical performance procedures are in [device validation](device-validation.md).
